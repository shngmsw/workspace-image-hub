Self-hosted · Google Workspace · WebP

ドライブの画像を、変わらない直リンクに。 Images from Drive, as direct links that never change.

Google ドライブやローカルの画像を一度だけ WebP に変換し、Google Chat・GitHub・Notion にそのまま貼れる直リンクを返します。Google Workspace の組織が自分たちで動かす、オープンソースのアプリです。

Workspace Image Hub converts an image from Google Drive or your computer to WebP once and hands back a permanent direct link for Google Chat, GitHub, or Notion. It is open source, and your Google Workspace organization runs it itself.

§ 01 Why

ドライブは、画像の置き場に向いていない。 Google Drive is a poor image host.

チャットのアバターや Issue の画像にドライブのリンクを使うと、たいていどれかにぶつかります。

Use a Drive link as a Chat avatar or an image in an issue, and you run into one of these.

  1. drive.google.com/file/d/…/view text/html

    共有リンクは画像ではないA share link is not an image

    開くと出てくるのは HTML のページで、画像そのものは返ってきません。

    It opens an HTML page, not the image itself.

  2. drive.google.com/uc?export=view&id=… 不安定fragile

    裏技の URL は壊れるThe workaround breaks

    uc?export=view で画像を直接取る方法は、Google 側の変更でたびたび使えなくなります。

    The uc?export=view trick stops working whenever Google changes it.

  3. drive.google.com/drive/folders/… 全ファイル公開every file public

    フォルダの公開は漏れるA public folder leaks

    アバター 1 枚のためにフォルダを公開すると、同じフォルダの他のファイルまで見えてしまいます。

    Make a folder public for one avatar URL, and every other file in that folder is exposed with it.

img.example.com/i/7k2m9q4xw1hc8d3v.webp image/webp

公開されるのは WebP だけOnly the WebP is public

元のファイル、登録した人のアドレス、ファイル名、タグは外に出ません。ID は 80 ビットの乱数から作る 16 文字なので、推測も一覧もできません。

The original file, the uploader’s address, the file name, and the tags stay private. The id is 16 characters from 80 random bits, so links cannot be guessed or listed.

§ 02 How it works

入れる、変換される、貼る。 Drop it in. Copy the link. Paste.

  1. 1

    画像を入れるBring an image

    ドラッグ＆ドロップ、ファイル選択、クリップボードからの貼り付け、Google ドライブのピッカー（複数選択・共有ドライブ対応）の 4 通り。JPEG、PNG、WebP、GIF、AVIF、TIFF を受け付けます。

    Drag and drop, choose a file, paste from the clipboard, or pick from Google Drive (multi-select and shared drives work). JPEG, PNG, WebP, GIF, AVIF, and TIFF are accepted.

    ドライブのファイルはブラウザがダウンロードしてからアップロードするので、サーバーはドライブのトークンを持ちません。ドライブのボタンは GOOGLE_PICKER_API_KEY を設定したときに表示されます。

    The browser downloads a Drive file and uploads it like a local one, so the server never holds a Drive token. The Drive button appears once GOOGLE_PICKER_API_KEY is set.

  2. 2

    一度だけ WebP に変換Converted to WebP, once

    長辺は 1024px に収め（拡大はしません）、画質は 80。アニメーション GIF はアニメーションのまま変換し、EXIF は出力に残しません。カードには変換前後のサイズが出ます。

    The long edge is capped at 1024 px (never enlarged) at quality 80. Animated GIFs stay animated, and EXIF data is dropped. Each card shows the size before and after.

    上限と画質は IMAGE_MAX_DIMENSION と WEBP_QUALITY で変えられます。

    Change the cap and quality with IMAGE_MAX_DIMENSION and WEBP_QUALITY.

  3. 3

    コピーして貼るCopy and paste

    URL そのままか、Markdown の ![ファイル名](URL) をコピーします。リンクは Cache-Control: immutable 付きで配信され、あとから変わりません。

    Copy the plain URL, or Markdown as ![file name](url). Links are served with Cache-Control: immutable and never change.

Google Chat の Webhook に使うときUsing it with a Google Chat webhook

Webhook の設定にある「アバター URL」の欄に、コピーした URL をそのまま貼り付けます。この欄は URL しか受け取りません。 README の説明

Paste the copied URL into the Avatar URL field in the webhook’s settings. The field takes a plain URL. Read more in the README

§ 03 Features

ひとつの組織で使うための作り。 Built for one Workspace organization.

  • ログインは許可したドメインだけSign-in limited to your domains

    「Google でログイン」で、ALLOWED_DOMAINS の Workspace アカウントと ALLOWED_EMAILS のアドレスだけを通します。ID トークンはサーバーが検証します。

    Sign in with Google admits Workspace accounts from ALLOWED_DOMAINS and addresses in ALLOWED_EMAILS. The server verifies the ID token.

  • タグと検索のライブラリA library with tags and search

    全画像を新しい順に並べます。ファイル名・タグ・登録者・ID で検索でき、大文字と小文字、ひらがなとカタカナの違いは無視します。

    Every image, newest first. Search file names, tags, uploaders, and ids, ignoring case and treating hiragana and katakana alike.

  • 変換前後のサイズSize before and after

    カードごとに元のサイズと変換後のサイズ、縦横のピクセル数を表示します。

    Every card shows the original and converted size, and the pixel dimensions.

  • 削除は本人か管理者Delete by owner or admin

    消せるのは登録した本人と ADMIN_EMAILS の人だけ。キャッシュ済みのコピーまでは回収できないことも、確認ダイアログで伝えます。

    Only the uploader or someone in ADMIN_EMAILS can delete. The confirmation says that cached copies may keep showing for a while.

  • データベースなしNo database

    画像と記録（登録者、元のファイル名、タグ）はファイルかオブジェクトとして置くだけ。ローカルならボリュームをコピーすればバックアップです。

    Images and records (uploader, original name, tags) are plain files or objects. On local disk, copying the volume is the backup.

  • ローカルディスクか Cloud StorageLocal disk or Cloud Storage

    保存先は Docker ボリュームか Cloud Storage。公開バケットを使う構成なら、アプリが止まっていても画像は表示されます。

    Store images on a Docker volume or in Cloud Storage. With a public bucket, links keep working while the app is down.

  • 設定は環境変数だけEnvironment variables only

    どの組織でも同じビルド済み Docker イメージを使います。設定に誤りがあれば、起動時に問題を全部並べて終了します。

    Every organization runs the same prebuilt Docker image. A bad value stops startup with every problem listed at once.

  • 日本語と英語の画面Japanese and English UI

    APP_LOCALE で固定するか、利用者の切り替えとブラウザの言語に任せます。

    Pin one with APP_LOCALE, or let each user’s toggle and browser language decide.

  • MIT ライセンスMIT license

    ソースコードはすべて GitHub で公開しています。

    All of the source code is on GitHub.

§ 04 Get started

動かし方は 2 通り。 Two ways to run it.

どちらも同じ Docker イメージです。先に Google Cloud で、種類「ウェブ アプリケーション」の OAuth クライアント ID を作っておきます。 共通の準備

Both run the same Docker image. First, create an OAuth client id of type Web application in Google Cloud. Common setup

方法 1Option 1

Docker Compose

自分のサーバーや PC で動かし、画像は Docker ボリュームに保存します。まず試すならこちら。

Runs on your own server or PC and keeps images in a Docker volume. The quickest way to try it.

  1. OAuth クライアントの承認済みの JavaScript 生成元に http://localhost:3000 を登録し、2 つのファイルを取得します。

    Add http://localhost:3000 to the OAuth client’s authorized JavaScript origins, then fetch two files.

    sh 
    mkdir image-hub && cd image-hub
curl -fsSLO https://raw.githubusercontent.com/shngmsw/workspace-image-hub/main/compose.yaml
curl -fsSL -o .env https://raw.githubusercontent.com/shngmsw/workspace-image-hub/main/.env.example

  2. .env の必須 4 項目を埋めます。AUTH_SECRET は openssl rand -base64 32 で作ります。

    Fill in the four required values in .env. Generate AUTH_SECRET with openssl rand -base64 32.

    .env 
    APP_URL=http://localhost:3000
AUTH_SECRET=<openssl rand -base64 32>
GOOGLE_CLIENT_ID=123456789012-abc123.apps.googleusercontent.com
ALLOWED_DOMAINS=example.com

  3. 起動して http://localhost:3000 を開き、許可したドメインの Google アカウントでログインします。

    Start it, open http://localhost:3000, and sign in with a Google account on an allowed domain.

    sh 
    docker compose up -d
README「方法 1: Docker Compose」 README: Option 1, Docker Compose

方法 2Option 2

Cloud Run

Google Cloud で動かし、画像は Cloud Storage に保存します。サーバーを持たずに運用するならこちら。

Runs on Google Cloud and keeps images in Cloud Storage. For running without a server to maintain.

  1. 非公開バケット（と任意の公開バケット）、サービスアカウント、AUTH_SECRET 用のシークレットを用意します。コマンドは README にあります。

    Create a private bucket (and optionally a public one), a service account, and a secret for AUTH_SECRET. The README has the commands.

  2. リポジトリの Dockerfile を Cloud Build でビルドしてデプロイします。

    Build the repository’s Dockerfile with Cloud Build and deploy it.

    sh 
    git clone https://github.com/shngmsw/workspace-image-hub.git && cd workspace-image-hub
gcloud run deploy "$SERVICE" --source . --region="$REGION" --service-account="$SA" \
  --allow-unauthenticated --memory=2Gi --concurrency=10 \
  --set-env-vars="APP_URL=$APP_URL,STORAGE_DRIVER=gcs,GCS_BUCKET=$PROJECT_ID-hub,GCS_PUBLIC_BUCKET=$PROJECT_ID-hub-public,GOOGLE_CLIENT_ID=123456789012-abc123.apps.googleusercontent.com,ALLOWED_DOMAINS=example.com" \
  --set-secrets="AUTH_SECRET=hub-auth-secret:latest"

  3. 組織ポリシーで allUsers への公開が禁止されている場合の構成も、README で説明しています。

    If org policies forbid granting allUsers, the README covers that setup too.
